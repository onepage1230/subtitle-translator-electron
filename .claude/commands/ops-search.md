# ops-search — 搜尋派工模板

在 repo 內「找東西」的標準流程。主對話不自己下場 grep 或整檔讀（守則見 `docs/ops/02-delegation.md` §1）。

## 步驟

1. **先判斷是不是 codegraph 就能答**：如果問題是「某個已知符號在哪／誰呼叫它／改了影響誰」，直接用 `codegraph_context` 或 `codegraph_callers`，2–3 次呼叫答完就結束，不派工。

2. **填派工單**（缺一欄就先補齊再派）：

   ```text
   【目標與動機】找出：$ARGUMENTS
   為什麼要找：＿＿＿（找到之後要拿來做什麼）
   【搜尋範圍】必須涵蓋：＿＿＿（目錄清單，例如 electron/main/ 與 src/ 兩側）
   【已知線索】＿＿＿（已知的檔案、關鍵字、命名慣例；沒有就寫「無」）
   【驗收條件】
   - 每個結論附 檔案:行號
   - 範圍內某個目錄完全沒有命中時，明確回報「無」，不可省略
   - 只調查，不修改任何檔案
   【回報格式】(1) 結論 ≤5 行；(2) 證據清單：`檔案:行號 — 一句話`；(3) 沒找到的部分明說。
   不貼程式碼全文；清單超過 30 行寫到檔案回傳路徑。
   ```

3. **派工**：Agent tool，`subagent_type: Explore`，`model: sonnet`。搜尋廣度在 prompt 中註明（一般寫 "medium"；要掃多個目錄與命名變體寫 "very thorough"）。

4. **收貨檢查**：回報中每個結論都有 檔案:行號 嗎？沒有的結論不採用，退回補證據（計入重試，上限見 `02-delegation.md` §5）。

## 注意事項

- 結果要拿去改程式的話，改動本身另走 `/ops-implement` 或直接修（單點小改）。
- 搜尋兩次都找不到 ≠ 不存在；回報使用者時要說「在範圍 X 內未找到」，不要說「不存在」。
